## 总项目与两个子项目

Migo Personal Brand Ecosystem 是统一的个人品牌总项目，下设两个独立管理的项目。它们共享品牌一致性要求，但不合并成一个代码仓库。

| 项目 | 名称与位置 | 主要职责 |
| --- | --- | --- |
| Project A | Migo × Beedog Brand Identity；[品牌项目资料](01_品牌设计项目/README.md)位于 AIGC 仓库的作品项目/Migo个人品牌总项目/01_品牌设计项目 | 品牌策略、定位、命名和故事；Migo Logo；Beedog 原创角色、三视图、表情及动作；色彩、字体、辅助图形、视觉识别、品牌手册和设计源文件 |
| Project B | Migo Personal Portfolio Website；[独立网站仓库](https://github.com/Migo1203/migo-portfolio)负责网站规划与后续设计开发；[网站入口与品牌交接](02_网站项目入口与品牌交接/README.md)位于本总项目目录 | 网站策略与信息架构、Sitemap、Wireframe、UI 视觉、Astro / TypeScript / Tailwind CSS 开发、中英文内容、响应式页面、交互、SEO、性能、部署与维护 |

**实际仓库状态：** Project A 是 AIGC 仓库中的独立项目目录，AIGC 还包含其他作品。用户已创建 [Migo1203/migo-portfolio](https://github.com/Migo1203/migo-portfolio)，2026-11-09 已核实可访问，并将原 Project B 网站规划、内容及品牌接入记录迁入该独立仓库。AIGC 的原网站目录改为“02_网站项目入口与品牌交接”，只保留入口和品牌接入规范。网站尚未初始化源码或部署，阶段一仍待用户验收。

## 职责与权威来源

1. **品牌策略与设计的来源是 Project A。** Migo 是设计师与品牌主体，Beedog 是 Migo 的原创品牌角色；网站不重新定义两者关系。
2. Project A 负责品牌设计源文件、决策、规范和已经确认的资产导出；Project B 负责网站本身的规划、设计、实现与维护。
3. Project B 可以独立开展信息架构、内容结构和技术准备；实际品牌视觉使用以 Project A 中已确认的相应资产和规范为依据。未确认部分必须明确标为 [待确认]。
4. 网站所需的尺寸转换或技术优化应保持已确认的视觉含义和适用规则；对品牌定义、标识、角色原型或色彩规范的设计变更回到 Project A 处理。
5. Project B 使用独立副本或构建产物，不反向覆盖 Project A 的设计源文件。两个项目可分别迭代，并记录资产版本与使用位置。

## 资产流转

Project A 创作与确认 → 在[品牌资产清单](品牌资产清单.md)登记状态、来源版本和使用条件 → 导出适用于网站的文件 → Project B 按[网站品牌接入规范](02_网站项目入口与品牌交接/网站品牌接入规范.md)集成 → 如需设计变化，在 Project A 更新并重新交付。

确认以实际决策和记录为依据，不将文件存在、上传或网站引用自动视为已确认。两条工作线的阶段与依赖见[总项目路线图](总项目路线图.md)。

## 本轮迁移与后续维护

按用户“我已创建好新仓库，帮我迁移文件和改名”的指示，网站资料迁入既有的 migo-portfolio 仓库，保留其初始化提交；原目录改名并更新导航。本轮没有创建其他仓库，没有制作线框、UI、网站代码或品牌视觉资产。网站准备文档在网站仓库维护，品牌源文件继续留在 Project A，避免两处重复维护同一份网站计划。
