# 网站品牌接入规范

适用范围：Project B Migo Personal Portfolio Website 使用 Project A Migo × Beedog Brand Identity 的品牌资产。网站项目独立管理，网站 UI 与代码不存入本品牌项目作为合并代码仓库。

## 基本规则

- Migo 是设计师与品牌主体；Beedog 是 Migo 的原创品牌角色，不是另一位独立设计师。网站文案、署名和界面须保持这一关系。
- 网站只将 Project A 中**已确认且适用于网站**的视觉资产作为正式品牌资产使用，并按[资产清单](../品牌资产清单.md)记录来源版本与使用条件。
- 未完成或未确认的 Logo、角色、字体、色彩与图形均标为 Pending / [待确认]。网站规划或原型如需临时占位，须明确其为占位内容，不得将其描述为正式品牌设计。
- Project B 不自行修改品牌定义，也不反向改写 Project A 的设计源文件。涉及品牌设计变更时回到 Project A 记录和处理。

## 各类资产如何调用

| 资产 | 网站使用原则 | 当前状态 |
| --- | --- | --- |
| Migo Logo | 使用已确认的 SVG 或 PNG 及其适用变体；遵守实际规定的比例、留白、背景与尺寸。 | Pending |
| Beedog 标准形象 | 以品牌角色身份出现，服务于内容与互动；具体位置、比例和出场频率 [待确认]。 | Pending |
| Beedog 表情与动作 | 仅使用已确认的相应版本；表达须符合角色规范，不能将角色写成独立设计师。 | Pending |
| 字体 | 核查实际许可、网页嵌入和中英文覆盖；字体及回退方案待 Project A 和网站使用需求确定。 | Pending |
| 色彩 | 从已确认的 JSON 或 CSS 变量与使用说明接入；不把临时 UI 值写成最终品牌色。 | Pending |
| 品牌图标与辅助图形 | 使用已确认的图形及适用规则；界面功能图标体系与品牌图形的边界 [待讨论]。 | Pending |

品牌视觉规范、适用版本与授权尚未确认时，不自造“正式规则”。网站的 Sitemap、Wireframe、内容组织和非品牌技术工作可以独立推进，但本轮不实施。

## 文件接收与变更流程

1. Project A 完成并确认具体资产后，在清单记录实际文件、格式、尺寸、用途、来源路径、版本 / 提交、确认依据和使用条件。
2. Project B 引用该确认版本，按网站仓库的实际结构保存独立副本或构建产物，并记录使用位置；不得依赖修改 Project A 源文件。
3. 为性能进行格式转换、压缩或按需缩放时，保持已确认造型、比例与授权条件；如调整改变品牌视觉或超出既定规则，回 Project A 处理。
4. Project A 更新资产后，Project B 对照版本、展示效果与授权重新集成；两个项目分别保留各自版本和变更记录。
5. 网站正式使用某项品牌视觉前，确认该项资产及相应用法已在 Project A 登记。可逐项交付，不必假设所有品牌资产会同时完成。

## 技术与项目边界

网站计划采用 Astro、TypeScript、Tailwind CSS，提供中英文内容、响应式页面、交互、SEO 与性能优化；这些是 Project B 的既定方向，不代表仓库、代码或部署已存在。其仓库地址与可访问性 [待确认]。跨项目依赖见[总项目路线图](../总项目路线图.md)。
