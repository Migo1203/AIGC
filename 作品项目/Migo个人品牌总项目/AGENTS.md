# Migo Personal Brand Ecosystem 协作约定

每次开始相关工作，先阅读本目录 README，以及 01_品牌设计项目 下的 01_品牌策略/品牌项目简报.md、01_品牌策略/品牌架构.md、07_项目管理/品牌决策日志.md、07_项目管理/品牌任务清单.md 和任务涉及的阶段资料。保留用户已有工作；发现新要求与既有决策冲突时，记录差异并以用户最新明确指示为准。

品牌共同背景读取 `01_品牌设计项目/01_品牌策略/品牌设计简报_讨论稿.md`。该文件按 brand-context 框架整理，区分本人说明、建议和研究缺口；它仍是讨论稿，不表示用户整体确认。个人资料以 Migo 仓库为维护源，品牌背景在本项目维护，不另建重复的 `.agents/brand-context.md`；文件存在不代表技能会自动加载。

- 涉及网站或跨项目资产时，还须阅读 总项目架构.md、品牌资产清单.md、02_网站项目入口与品牌交接/网站品牌接入规范.md 和 总项目路线图.md。Project A 品牌设计与 Project B 网站独立管理，不能合并代码仓库；网站只将 A 已确认的资产作为正式品牌视觉，未确认部分明确标记。
- Project A 是品牌定义和设计源文件的来源；网站不得改写品牌定义或反向覆盖 A 的源文件。网站仓库已核实为 https://github.com/Migo1203/migo-portfolio，网站规划、内容与后续代码在该仓库维护；本仓库的 02_网站项目入口与品牌交接 仅保留入口和品牌接入规范。仓库存在不等于网站代码或部署已经完成。
- 项目普通文件与文件夹使用中文名称；按用户确认保留 README.md 和 AGENTS.md 两种工具识别文件名。
- Migo 是设计师和品牌主体；Beedog 是其原创品牌角色，不是另一个独立设计师。BD 暂不作为独立对外品牌。
- 按策略研究、视觉概念、角色、品牌识别、应用和规范的先后顺序工作；不得把尚未完成的阶段写成定稿。用户另行明确调整顺序时，以最新指示为准。
- 区分用户已确认的信息、[待研究]、[待讨论]、[待验证]和建议；不替用户选择视觉方向或宣称用户认可。
- 记录参考来源原始链接、实际查看范围与日期。未实际看到图片时，不编造对构图、颜色、形态或视觉效果的观察。外部案例用于分析，不直接复制其受保护素材。
- Beedog 的网络表情包仅为用户提供的灵感线索；不描摹、复制或商业化使用原照片，原创性相关结论也须有实际比对依据。
- 默认中文，必要时保留英文术语。重要决策与变更记录到决策日志，同时更新相关策略文档和任务清单。
- 2026-11-08 的启动轮要求不绘制角色、不生成图片，文件先供用户检查，暂不提交或推送；后续按用户最新明确授权执行。
