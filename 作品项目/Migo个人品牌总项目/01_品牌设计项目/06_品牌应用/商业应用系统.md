# 商业应用系统｜触点与交付框架

状态：商业触点清单和判断方法，尚未确定具体服务、价格、合作模式或已完成的商业物料。Migo 是设计师和商业服务主体；Beedog 辅助品牌人格化。

## 1. 已知范围

用户希望建立专业可信、具有长期商业延展能力的个人品牌，并计划通过小红书和作品集展示。网站属于独立的 Project B；本项目负责品牌视觉资产与适用规范。

## 2. 候选应用场景

| 场景 | 品牌项目可准备的内容 | 需要先确定 | 状态 |
| --- | --- | --- | --- |
| 线上展示与联系 | 已确认的品牌标识、角色与适用规则；社交主页视觉素材 | 实际渠道、信息与品牌资产 | 用户已指定小红书和作品集；具体设计待定 |
| 商务沟通 | 可复用的介绍、提案或项目沟通材料中的品牌视觉规则 | 受众、服务内容、联系方式和使用场景 | [建议，待讨论] |
| 项目交付 | 在说明文档或作品展示中保持署名、信息与资产使用一致 | 真实项目流程、交付范围和客户约定 | [建议，待讨论] |
| 实体与周边 | 根据实际需求研究名片、印刷物或角色衍生品等 | 用途、预算、制作条件和授权 | [建议，待讨论] |
| 角色合作与授权 | 整理 Beedog 的使用范围、资产版本和授权边界 | 角色定稿、权利及合作形式 | [待讨论]，不表示已开展授权 |

表中除用户指定触点外均为候选，不代表用户已经选择、制作或开展相应业务。

## 3. 场景评估与优先级

每选择一个应用，先记录使用者、要传达的信息、Migo 与 Beedog 的关系、所需品牌资产、媒介限制、预算及预期使用方式；再判断是否真的需要制作。

优先级可按 **实际需求、已有内容、品牌资产成熟度和投入** 综合讨论。具体排序 [待讨论]；未确认 Logo、字体、色彩或角色时，只能将相应用途标为候选，不能声称正式交付。

## 4. 交付与验收

每项应用至少记录：名称与用途、受众、实际尺寸 / 格式、源文件与导出、使用素材的来源与许可、品牌版本、用户反馈及最终状态。对商业合作信息和可公开内容以实际约定为准。
