# Migo 设计原则｜讨论稿 V01

日期：2026-11-11。阶段：案例比较后的策略收敛。用户要求“横向归纳，提炼 Migo 的设计原则”；本文已完成提炼，新增原则和应用建议仍待本人审阅及实际设计验证，不代表视觉方案定稿。

依据：[六案例横向归纳](../../03_学习资料/案例分析/品牌设计案例/六案例横向归纳.md)、[共同背景](品牌设计简报_讨论稿.md)、[品牌架构](品牌架构.md)、[本人设计输入](个人品牌探索/品牌自述与设计输入.md)与[学习反馈](../../03_学习资料/案例分析/品牌设计案例/Mailchimp/02_学习反馈与品牌表达.md)。本轮没有新增外部视觉观察或生成设计图。

## 1. 已有约束与本轮建议分开使用

**用户已明确：** 近期深圳 AIGC／视觉岗位求职优先，兼顾未来接单；希望创意和想法被看见，品牌年轻、有独立内核、认真细致，可以不可爱。Migo 是本人及主品牌，Beedog 是品牌角色，通常通过动作和情绪表达，项目设计说明由 Migo 负责。文字倾向愿意解释原因、亲切直接、克制简洁，少用网络热词但不绝对禁止。

**本人提出的探索兴趣：** 真人电影大黄蜂带来的黑黄、蜂巢、机械结构、科技感和性格反差。它们可以参与概念比较，尚未成为必选色板、造型或世界观。

**本轮建议的总体方向：**

> 用清楚的秩序承载丰富的想法，让好奇心通过角色行为与真实创作过程被看见。

这是帮助后续选择的内部方向，不替换“好奇探索，认真设计”，也不是新的对外口号。

“设计原则”是面对方案时用来取舍的标准；“风格”是具体呈现方式。原则可以先明确，色彩、媒介与造型仍可比较。

## 2. 七条候选设计原则

### P01｜身份清楚，作品支持专业判断

**依据：** 用户求职目标与既定架构；Mailchimp 的角色／业务分工、GitHub 的资产职责、Big Tea 的信息层级。

**建议规则：** 初次介绍让人找到 Migo 名称、设计方向与作品入口；案例说明交代问题、本人贡献、关键取舍和成果。Beedog 可以帮助建立记忆，不承担证明全部能力的任务。

**判断问题：** 隐去角色后，读者是否仍知道你是谁、做了什么？加入角色后，是否更容易理解或记住，而没有遮挡必要信息？现有自主项目、AI 协助与未来学习计划是否分别表述？

“独立设计师品牌”可表达长期模式；求职介绍仍按真实经历写，不暗示已有正式工作、客户委托或成熟服务。

### P02｜形式与个人经历、想法和选择建立联系

**依据：** 本人希望建立属于自己的品牌；GitHub 从产品贡献图延展图形的方法、Slligy 将个人创作与身份表达结合的展示。

**建议规则：** 每个主要概念说明“来自什么真实输入、想表达什么、为什么采用这种形式”。个人联系可以由故事和创作过程补充，不要求每个元素都藏在 Logo 中，也不事后编造意义。

**判断问题：** 如果拿掉蜜蜂、狗、黑黄和科技感标签，还能说明这个概念为什么属于 Migo 吗？不同方案的差异是否来自想法与结构，而不仅是换材质和颜色？

蜂巢、机械与黑黄是常见语言，单独采用不能证明独特。原创性需结合实际方案和参考比对；不移用表情包照片、电影角色的标志性零件组合或参考品牌的具体形象。

### P03｜先建立稳定识别，再扩展变化

**依据：** Duolingo 的轮廓与构形探索、Discord 的表情矩阵、Mailchimp 的深底专用版本。

**建议规则：** 选定基础形象后，记录关键轮廓、比例、部件关系与允许变化的范围，再扩展视角、动作和媒介。单色、深浅背景和小尺寸版本要逐一检查。

**判断问题：** 去掉材质、颜色与装饰后，还剩哪些独有关系？改变动作后哪些特征必须保留？机械线与蜂巢细节缩小后帮助识别，还是形成杂讯？

当前不预定具体脸型、耳朵、眼睛、机械程度，也不因 GitHub 的案例就新增独立图形 Logo。

### P04｜用行为表达人格，保留情绪与反差

**依据：** 用户对 Beedog 非语言表达的要求；Big Tea 的动作情境、Discord 的眼部变化、Duolingo 的任务反馈。

**建议规则：** 先写角色处于什么情境、注意什么、怎样反应，再设计动作。好奇、认真、笨拙可以共存，不把 Beedog 塑造成永远正确的设计专家。

**候选行为：** 靠近观察细节、对照不同选择、停顿思考、试验不顺后重新调整。这些是待测试的情境，并非标准动作已确定。

**判断问题：** 不加台词和情绪标签，观者能读到什么？是否出现明显误解？动作表达了探索过程，还是只剩泛化的卖萌？

用户已明确可以不可爱；脸型、材质或严肃表情都不直接等于有内涵。性格反差的具体两端仍待本人选择，通常不说话也不扩大为永久禁言。

### P05｜用信息秩序体现细致，按场景调节表现强度

**依据：** 已确认的语言倾向；Mailchimp 的排版与网页主次、Big Tea 的多触点应用、GitHub 的颜色与角色分工。

**建议规则：** 字标负责名称的特定形式，标题和正文负责阅读；颜色分别服务识别、角色和信息强调。构图、字体与图形保留一致关系，角色面积、动作幅度和配色面积可随内容目的调整。

**判断问题：** 核心信息是否突出，说明是否易读，字距、行距、对齐和术语是否一致？去掉角色后是否仍有可辨认的视觉秩序？图形是否有实际职责？

克制简洁不等于所有画面都冷淡或严肃；年轻新潮也不等于高饱和、金属或热词。专业内容的清楚与准确优先，活泼场景和程度见下表候选安排。

### P06｜在实际用途里检验设计

**依据：** Discord 对小表面及材料限制的说明、Mailchimp 的背景适配、各案应用与规范的区别。

**建议规则：** 用计划使用的头像、作品封面、案例开篇和过程内容检查设计；除展示大图外，还看实际显示尺寸、裁切、单色和不同背景。先发现问题，再建立对应规则，不照抄参考品牌的数值。

**判断问题：** 名称是否读得出，角色关键特征是否保留，正文是否受干扰？不同概念是否在同样内容与场景下比较？陌生读者的理解与本人意图有何差别？

小规模反馈用于发现问题，记录人数、情境和原话，不推算普遍识别率或求职成功率。实际认真细致通过修正落实，不能只靠精致样机宣称。

### P07｜建立能持续维护的系统，保留自己的决策记录

**依据：** 用户用 AI、Codex、GitHub 与 SOP 协作的实践，以及六案对资产规模和变体的提示。

**建议规则：** 先做能支撑近期求职与表达的基础资产，再按真实需求增加动作和应用。记录概念由谁提出、AI 协助什么、本人如何筛选和修改；为采用版本维护来源、用途、可编辑文件和状态。

**判断问题：** 新资产解决什么问题？下一次使用能否复现并修改？AI 生成中的结构漂移是否被发现和修正？是否有真实证据支持效率、能力与原创性表述？

AI 辅助是方法，创意、判断与完成质量需要具体证据。完整三维、复杂动画、周边和大量表情不是启动前置条件；本次也未规定必须采用何种制作工具。

## 3. 触点与表达强度｜候选，待讨论

“触点”指别人接触品牌的具体场景。下表安排的是注意力和角色任务，不是固定面积，也未确认哪些场景正式采用活泼文案。

| 场景 | 优先内容 | Beedog 的候选任务 | 语气建议 |
| --- | --- | --- | --- |
| 求职介绍、简历相关材料 | 身份、方向、作品与联系方式 | 少量识别或不出现，避免影响阅读 | 直接、准确、简洁 |
| 作品封面与案例开篇 | 项目成果、标题、本人职责 | 按需要辅助署名或引导，不覆盖关键成果 | 亲切清楚，必要处解释原因 |
| 设计过程与方法分享 | 问题、试验、取舍和修正 | 用观察、疑惑、尝试等动作辅助情绪 | 可有轻松时刻，程度待本人确认 |
| 个人介绍与品牌自述 | 名称、个人联系、方向与作品入口 | 与名称共同建立联系，增加人格表达 | 亲切直接，故事保持真实 |
| 角色实验、阶段完成记录 | Beedog 与探索过程 | 可作为主角，允许更大动作或反差 | 可更活泼是建议，尚未采用 |
| 未来合作范围或重要说明 | 事实、责任、交付和条件 | 可不出现，或仅作辅助识别 | 清楚、认真，避免玩笑干扰 |

角色露出、视觉强度和语言活泼程度可以分别调整，不需要同步提高。

## 4. 发生冲突时，建议怎样取舍

| 冲突 | 当前建议的取舍 |
| --- | --- |
| 名称和作品可读性 vs. 装饰完整 | 先保证主体与内容读得清，再调整装饰 |
| 个人契合 vs. 流行科技外观 | 优先能说明个人联系的方向，把流行形式当作可替换手段 |
| 行为表达 vs. 机械细节密度 | 先保留能支持识别与动作的结构，再加有用途的细节 |
| 品牌统一 vs. 每页完全相同 | 保留关键规则，允许围绕内容变化主次 |
| 清楚说明 vs. 强行幽默 | 先让读者理解，再判断幽默是否合适 |
| 完整交付清单 vs. 当前可维护范围 | 先验证近期真正使用的资产，其余随需求迭代 |

这套取舍服务当前阶段，后续有新目标或证据可以修订，不设未经验证的权重评分。

## 5. 进入视觉概念前保留的具体选择

- **个人内涵：** 选择真实想法、经历或创作态度，说明希望它怎样进入项目；不需要先编一整套世界观。
- **反差：** 比较外在结构与情绪、笨拙与专注等不同关系，确定哪一种更像本人。
- **视觉变量：** 机械化程度、黑黄是否采用、蜂巢作用、二维或立体、字标和字体均未选择。不同方向应在概念和结构上有差异。
- **应用边界：** 上表哪些场景更活泼、Beedog 露出多强、是否需要独立图形标识，仍待实际方案与本人反馈。

下一步可用这些原则撰写视觉概念任务书：先比较概念依据、关键形态和取舍，再用相同内容与触点做小范围验证。不以补齐所有历史资料为前提，也不将本文保存当作本人认可或自动进入生图、三维和网站开发。
