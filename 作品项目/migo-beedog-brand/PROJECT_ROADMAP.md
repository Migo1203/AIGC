# Migo Personal Brand Ecosystem｜总项目路线图

更新日期：2026-11-08。两条工作线独立管理；表中为计划，不代表网站仓库、代码、视觉资产或部署已经完成。品牌项目原有 Phase 0–7 细节继续见[品牌路线图](Project_A_Brand_Identity/07_Project_Management/Roadmap.md)。

## Project A｜品牌设计

| 阶段 | 任务与交付物 | 前置依赖 | 状态 |
| --- | --- | --- | --- |
| A0 / Phase 0 | 初始化、项目简报、架构、任务与资料入口 | 用户启动指令 | 文档已建立，品牌方案仍待审阅 |
| A1 / Phase 1 | 品牌案例、趋势与策略研究；交付结构化案例、比较与策略建议 | A0 | [待研究] |
| A2 / Phase 2 | 视觉 DNA 与角色概念；交付可比较方向及依据 | A1 的研究与必要策略结论 | [未开始] |
| A3 / Phase 3 | Beedog 标准形象、表情、动作与三视图；交付角色源文件与规范 | A2 的方向选择 | [未开始] |

Project A 的作品集应用指品牌资产和视觉规范的适配与交付；网站策略、页面 UI、开发和部署属于 Project B。

## Project B｜个人作品集网站

| 阶段 | 任务与交付物 | 前置依赖 | 状态 |
| --- | --- | --- | --- |
| B0 网站策略 | 明确受众、网站目标、中英文内容与项目范围；交付网站策略及需求清单 | 品牌主体关系和用户目标；无需等待全部视觉资产 | [待讨论] |
| B1 信息架构 | 制作 Sitemap、内容结构与 Wireframe | B0 的必要需求；可以与 A1–A3 并行 | [未开始] |
| B2 网站 UI | 制作响应式页面和交互视觉方案；品牌未定部分标注 [待确认] | B1；正式品牌视觉须使用 A 已确认的相应资产与规范 | [未开始] |
| B3 技术实现 | 在独立的 migo-portfolio 仓库开展 Astro、TypeScript、Tailwind CSS 实现 | 仓库地址与可访问性确认、B0–B1 的必要输入；非品牌技术准备可与 A 并行 | [未开始] |
| B4 集成与质量 | 接入已确认品牌资产，完善中英文、响应式、交互、SEO 和性能 | B2–B3 的相应成果；每项正式品牌资产须由 A 确认并登记 | [未开始] |
| B5 部署与维护 | 完成上线前检查、部署记录及后续维护 | B4 与实际部署条件 | [未开始] |

## 跨项目依赖与交付

品牌资产可以逐项交付：Project A 对某项资产完成设计、确认和来源记录后，Project B 即可按其适用范围接入；不必等所有角色表情或全部品牌应用完成。网站中仍缺少的品牌项保持 [待确认]，不将临时方案作为正式品牌资产。

网站的信息架构、Wireframe、内容策略及非品牌技术准备可以与品牌研究并行；正式品牌视觉实施依赖 Project A 已确认的对应资产。具体交接、版本和授权要求见[品牌资产清单](BRAND_ASSET_MANIFEST.md)与[网站品牌接入规范](Project_B_Portfolio_Website/WEBSITE_BRAND_INTEGRATION.md)。

本次架构与目录整理不开发网站、不生成视觉资产，也不创建第三个 GitHub 仓库。
