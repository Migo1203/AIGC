# 电商视觉全流程 SOP v0.2｜自检与待完善

日期：2026-11-03。针对[试用版SOP](电商视觉全流程SOP-v0.2-试用版.md)记录已处理问题和未明确事项；下一项目中继续验证与完善，不代表已完成跨产品验证。

## 已检查并在试用版中处理

| 问题 | 检查与处理 |
| --- | --- |
| 只覆盖生图和PS，缺少商业策划 | 加入任务、事实、研究、卖点、视觉方向、图组职责、整套审稿和作品集环节。 |
| 每次改图都要走完整流程，执行负担大 | 增加单图/改稿与整套的适用区别；已有素材可直接复用，只重做受影响部分。 |
| 旧SOP的“用户生图、Codex不生成”可能被误当作永久分工 | 改为按用户当前指示决定制作方式，保留实际分工与来源记录。 |
| 把音箱参数或画幅写成所有产品的规则 | 通用流程不固定96g、10小时、配色、屏数、像素或平台要求；产品事实及条件按项目核验。 |
| 图像生成、选用、审核、归档和推送容易混为一谈 | 分开记录候选、选用、排版、待核实、交付和本地/远程同步状态。 |
| 只审错字、对齐，忽略商业表达和系列重复 | 将审稿分为事实与产品、单图与整套、修改复核三层，并保留“卖点→画面”的诊断。 |
| “验证两种关键画面”容易被理解成单图任务也必须做两张 | 明确该做法供整套项目使用，单张任务按需要验证。 |
| 排版原则较多，但缺少实际执行顺序 | 补充从建画布、放产品到加文字、预览和保存的PS操作顺序；具体尺寸按任务确定。 |
| 用户与Codex在各步骤的分工不够明确 | 已补充逐阶段分工表，区分用户判断、PS操作及Codex整理、制作和检查；默认分工仍由用户修改。 |
| 参考研究容易被误解为只在项目一开始进行 | 按用户建议，明确制作前先做整体参考研究；制作中遇到具体卡点时定向补找，再回到当前图片。 |
| 启动阶段没有单独写清项目背景与分工 | 按用户建议，在任务启动时先写项目缘由、目标和使用场景，同时明确用户与Codex的实际分工。 |
| 文案制作只有零散提及，先后关系不清楚 | 按用户建议，明确卖点阶段拟定主张，分图规划后撰写标题、Slogan和条件，排版后再次复核。 |
| 不清楚什么时候调用什么Skill | 加入阶段与Skill/工具对照，并单独保留调用复盘；候选方法与新Skill需求标为待验证。 |

## 未明确或待下一项目验证

1. **流程颗粒度：** 本稿覆盖完整项目，实际使用是否过长、哪些阶段需要合并或增加示例，由用户根据自己的工作习惯修改。
2. **具体任务分工：** 已添加建议分工表；每个项目中哪些步骤由用户操作、哪些由Codex完成，按实际要求调整。
3. **研究深度：** 竞品、评论和平台规则的工作量随项目目标和可得资料变化；下一项目需验证当前记录方式是否够用，不能事先声称已经验证。
4. **操作与模板：** 已提供一张单图任务卡；是否需要独立的项目总表、PS图层模板、审稿表或命名模板尚未确定，按下一项目的实际需要补充。
5. **实际可复用性：** 目前主要来自一个产品项目；下一项目记录哪些步骤有帮助、哪里仍返工，再按真实结果迭代，不预设提效数字。
6. **Skill调用与优化：** 已提出阶段调用建议；`art-direction`等候选是否适合、是否需要新建或修改Skill均待实际任务验证，不视为已安装或已完成优化。
7. **下个项目的具体输入：** 产品、平台、类目、目标、规格和授权等尚未提供；启动时按该项目资料填写，不沿用小度音箱的参数。
