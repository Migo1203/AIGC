# AIGC产品视觉制作SOP v0.1

更新：2026-10-25。根据[小度音箱首轮案例](../../作品项目/小度音箱/作品集案例.md)整理，供同一产品的新场景或下一款产品试用。当前完成了一个项目的三张概念海报，流程仍需在后续任务验证；没有已测量的提效数据。

## 目标与分工

目标是把“需求、素材、制作、审稿、归档”连成可重复执行的流程。每次只给当前一步，不要求用户重复已完成的选图、生成或上传。

| 参与者 | 负责什么 |
| --- | --- |
| Migo | 确定目标和审美取舍、提供资料；使用GPT等图像工具制作候选，在PS中裁切、调整与文字排版；保存源文件并提交结果 |
| Codex | 整理产品事实与素材、拆分当前任务、提供提示词或PS步骤、检查结果、更新归档与过程记录；按用户要求不生成示范图 |

## 按阶段推进

可直接复用已有合格素材，跳过已完成步骤。阶段通过后继续下一步；审稿意见指出需要调整的内容，不增加重复确认环节。

| 阶段 | 输入与本步动作 | 输出与通过标准 |
| --- | --- | --- |
| 1. 明确任务 | 产品、用途、受众、交付尺寸、主信息；区分已确认事实与创意设定 | 一张简短任务卡，每张图有明确职责；缺少关键事实时先补资料，其余合理假设写明后继续 |
| 2. 整理参照 | 产品照片、可用图片、规格与来源；识别外观特征及功能限制 | 可打开的参照链接与已确认事实；已有清楚合格的产品素材直接使用，不额外生成基准图 |
| 3. 制作场景 | 用户将参照原图作为附件输入图像工具，使用当前场景提示词；已有合格场景则跳过 | 保存选中的原始底图与实际提示词；产品主要识别特征保留、光影与道具关系可信、具有排版空间 |
| 4. PS调整与排版 | 选中底图、文案与系列样式；处理取景、裁切、局部调整和文字图层 | 分层PSD与预览图；产品真实感、主次、文字可读性与对齐成立，避免无意遮挡 |
| 5. 原图与系列检查 | 截图用于初审；采用版本核对实际导出文件，再检查事实、产品、场景和排版。仓库已有原图直接读取，不要求重传 | 每轮最多三个关键问题，说明修改动作；按实际成图是否达到目标判定，不死守旧提示词里的占比或像素建议 |
| 6. 归档与案例 | 通过本轮检查的新文件、实际工具与修改说明 | 归档名称与链接清楚、版本可追溯；整套检查后记录真实分工、选择依据与有代表性的修改过程 |

每个项目只在项目README维护当前任务与采用版入口；案例说明、历史制作记录和图片索引各自保存对应内容，避免在多份指南重复维护进度。每轮只更新实际受影响的记录。

尺寸、字体、字号、光线和产品占比由当前任务决定。不同画面可有不同构图；系列复用字体层级、色彩与识别特征，不要求所有元素位置和大小完全相同。平台主图、场景海报与作品集展示分别按用途规划。同套PS文字优先复制已采用源文件的图层样式，未读取PSD时不把栅格图片推断出的字体参数当作实测值。

## 出现问题时怎么选处理方式

| 问题 | 优先处理 |
| --- | --- |
| 标题、字距、对齐、说明重叠、普通局部调整 | 在现有PS文字或图片图层中修改 |
| 主体显小，但产品与道具比例正确，希望改为近景 | 尝试整体裁切或取景调整，检查边缘与排版空间；不把整体放大裁切误当作产品相对比例失真 |
| 产品严重走样、结构错误或需要大幅改变光影 | 先定位具体问题，再选实物抠图合成、局部图像编辑或重生成；完成后复核受影响部分 |
| 场景整体不符合目标 | 修改场景要求后再制作候选，保留原版本与更改原因 |
| 已有图已达到本步目标 | 直接进入下一步，不为执行流程而重新生成 |

先判断问题是否影响产品事实、阅读或当前表达目标。只修改需要改变的部分，保留用户明确接受的创意取舍。候选数量与迭代次数按实际问题决定，不规定必须生成若干轮。

## 每次使用的一张任务卡

```text
任务名称：[产品／场景／制作阶段]
本步目标：[谁看、要记住什么；这次只完成什么]
输入素材：[可打开的图片、事实资料、已选版本链接]
制作方式：[复用现有图／PS调整／用户生成；选择当前需要的一种]
执行内容：[需生成时给完整提示词与附件顺序；纯PS任务给具体操作步骤]
检查标准：[最多三项与本步有关的可观察标准]
输出文件：[阶段、尺寸、格式、文件名；PS任务保留分层源文件]
提交入口：[聊天预览或当前分类的GitHub上传链接]
本步完成后：[下一阶段，不提前展开全部后续操作]
```

需要生成时，提示词至少说明：每张附件的用途、产品要保留的特征、场景与光影、构图与排版留白、文字要求、已确认的功能限制。给过用户的建议词与用户实际执行的原文分别记录。

纯PS任务直接给“选哪个图层、改什么、怎样检查、如何保存”，无需附生图提示词。位置与尺寸建议标为起始值，最终按成图效果调整。

## 保存、命名与提交

- 作品按产品和场景存入对应目录，名称沿用 `用户上传-[产品]-[场景]-[阶段]-v01.png`。阶段可以是“无字”或“PS文字排版”。
- 底图与文字分别编号，例如无字v03可以对应首次文字排版v01。只有该阶段内容实际修改后才递增版本，改名、移动、同图再次上传不产生新制作版本。
- 同场景不同候选用内容或候选代号区分，选中后写明采用状态。已有合格图片直接引用原文件，不复制、重传或改写来源。
- `用户上传-`只标记提交来源。既有Codex示范保留原来源与采用关系，不因用户选用或上传就写成全部由用户独立生成。
- 用户先在聊天发预览，或上传GitHub并点击 **Commit changes**，然后通知Codex。Codex收到通知后同步、检查并分类，未运行后台自动监听。
- 整理时保留原文件名、实际工具、版本与修改原因；完全相同的重复内容复用已有文件和来源记录。具体约定见[图片命名规则](../../项目文档/image-library.md#图片来源与命名)。

## 本次音箱项目带来的经验

用户最满意第三张野餐图的构图与色彩。第二张原远景中产品在画面中显小，用户在PS中改为近景；其余PS工作以文字排版为主。制作本身没有特别困难，较多精力投入协作方式与任务流程的调整，目标是形成可复用SOP。

据此保留三个默认做法：先明确当前任务；能在现有图上用PS解决的问题直接调整；合格结果直接进入下一阶段。此前音箱画幅、色号、按键与无防水限制属于该项目参数，不写成所有产品的通用要求。
