## 图片来源与命名

从2026-10-24起，作品图片统一使用 `来源-对象-内容-版本.png`。已存在的版本号和候选代号保持不变。

| 文件来源 | 命名方式 | 存放位置 |
| --- | --- | --- |
| Codex生成或编辑的示范 | `Codex示范-音箱-窗边海报-排版-v01.png` | 音箱项目的“参考示范”文件夹 |
| 用户提交的作品图 | `用户上传-音箱-窗边海报-排版样图-v02.png` | 音箱项目的“制作结果”对应分类 |
| Codex生成的网站示意 | `Codex示范-首页视觉草稿.png` | 项目文档的“网站设计”文件夹 |
| 产品照片、商品宣传与规格附件 | 沿用“音箱-正面-N03.jpg”等内容名称与来源编号 | “素材/产品资料”对应分类 |

“用户上传”记录文件提交来源，实际生成工具、人工修改和创作归属继续按制作记录说明。若用户上传的文件源于Codex示范，保留两者的来源关系；相同内容不因再次上传就改记为用户独立创作。

版本号按来源和内容分别管理。相同的v03可能分别指Codex精修示范和用户上传稿，必须结合来源前缀识别。现有海报用户稿v02、v03的编号保持不变，后续用户修改版从v04继续。

原上传名、工具输出名及历史提示词原文继续保留，当前文件位置以[重命名对照表](image-rename-map.csv)的“现路径”为准。以后收到新图，先核对来源和文件内容，再按这一规则分类、命名和更新链接。

## 以后怎么命名和上传

- 新上传资料先比对文件内容；完全相同的文件保留一份，补充来源记录并复用已有文件。
- 本项目后续沿用以下约定：你上传图片并告知我后，我会同步仓库，按内容分类、统一命名，并更新图片索引和文档引用。
- 新样图先在对话中检查；检查合格后由你上传GitHub，再进行仓库归档。检查通过的范围会标明，例如“版式通过、产品细节待精修”。
- 每一步先说明当前任务目标、素材链接、可复制提示词、检查标准和上传位置。若提供Codex生成的示范，必须附用户可打开的图片链接，不仅引用工具中的预览。
- 先进入对应分类，再点击 **Add file → Upload files** 上传。
- 作品图片名称写明来源、对象与内容，例如 `Codex示范-音箱-居家阅读-无字-v01.png`、`用户上传-音箱-窗边主视觉-精修-v01.png`；产品参考资料沿用原来源编号。
- 相同内容的实际修改版本使用 `v02`、`v03`；不同构图用内容区分。
- 全部旧路径、新路径与内容校验值已记录在[重命名对照表](image-rename-map.csv)。
- 新制作示范图的原路径记录本次工具输出位置，仓库中的文件以“现路径”为准。
- 整理时保留图片内容、尺寸与格式；新上传且改名的文件继续补充旧名与新名对照。未选中的候选图保留作过程记录，完成选图后在索引里标注用途。
